# Career Profile (Personal Career LLM)

> **A dedicated "My Profile" page: career memory, skill ROI engine, and an AI career advisor that answers questions about your actual job-search data.**

## Overview

`/profile` (sidebar entry after Contact Tracker, `UserRound` icon) is a six-tab page:

| Tab | Purpose |
|-----|---------|
| **Profile** | Career profile CRUD (contact info, summary, goals, target roles/locations/salary) + seed-from-resume |
| **Experience** | Work experience entries + tracked skills (proficiency, category, years, last used) |
| **Education** | Career-graph education entries (add/edit/delete; auto-imported from resumes) + languages |
| **Projects** | Career-graph project nodes with GitHub/website links, languages + README; import from GitHub |
| **Achievements** | Career-graph achievements (title, details, `YYYY`/`YYYY-MM` date) + awards + certifications |
| **Skill ROI** | Job-focused "what to do next": skills to learn, skills to strengthen (with verified learning-resource links), everything else collapsed; optional LLM recommendation. Topped by the **Market Position** card: deterministic per-skill and per-domain percentiles plus a verdict sentence. The Experience tab's skills section also offers **AI skill suggestions** — "forgotten" skills with a one-sentence reason, addable in one click |

The overview/funnel stats live on the dashboard; the AI career advisor is its own `/chat` page.

## Key Design Decisions

- **Local-first, no external data sources.** ROI is computed from job descriptions saved via the Job Scraper (plus skills/proficiency the user tracks in the profile). Nothing is fetched from the web at request time (GitHub repo summaries reuse the existing optional GitHub token).
- **Career memory bundle.** Every LLM feature runs over one aggregated JSON snapshot (`build_career_memory()`) with hard caps so prompt size stays bounded (~35k chars): master resume ≤6000 chars, job descriptions ≤1500 chars each, 20 rejected applications, 25 scraped jobs, 50 contacts, 10 GitHub repos.
- **Funnel math is deterministic and null-safe.** Rates are `null` when the denominator is 0; `median_days_to_interview` is computed only from interview-stage cards (`applied_at` → `updated_at`).
- **ROI formula (weighted, 0–100):** `0.35 × jobs-unlocked% + 0.25 × salary + 0.20 × learning ease + 0.20 × existing knowledge`. Salary impact only counts when ≥3 matching jobs have parsable salary strings (`$80,000 - 100,000`, `$80k-$100k`, `€60K`); learning effort is `low`/`medium`/`high` from the skill catalog. By default the table lists catalog skills present in the job pool that the user doesn't track yet.
- **Every ROI row is classified into an action** (`learn` = missing from profile, `strengthen` = in profile + in demand + proficiency below 3/5, `monitor` = everything else). `partition_roi_rows` splits them into job-focused sections ranked by leverage (demand first, weakness second): **skills to learn**, **skills to strengthen**, and a collapsed "already strong / not in demand" list — the tab stops showing a flat dump of every skill.
- **Learning resources are LLM-proposed but server-verified.** `POST /profile/skill-resources` batches the visible gap/strengthen skills into one `SKILL_RESOURCES_PROMPT` call; every proposed URL is then fetched by `app/services/link_verifier.py` (http(s) only, 5s timeout, redirects followed, `<400` status, real `<title>` extracted) before it is cached in the `skill_resources` table (7-day freshness, `refresh: true` forces regeneration). Dead or hallucinated links never reach the UI; the table is UI-only — deliberately excluded from `career_data_fingerprint` so link refreshes never bust the chat-memory cache.
- **AI skill suggestions recall "forgotten" skills (LLM-optional).** `POST /profile/skill-suggestions` (`generate_skill_suggestions` in `app/services/career_profile.py`) builds a compact local snapshot (tracked skills + categories, work-experience roles, project names/languages, certifications — capped 40/10/10/10) and asks one `SKILL_SUGGESTIONS_PROMPT` call for 5-8 real, well-known skills that pair naturally with the profile. `_normalize_skill_suggestions` defensively drops unnamed entries, exact duplicates (case-insensitive) and anything already in the profile (again case-insensitive, so the LLM can't re-list tracked skills), truncates name/reason (100/200 chars) and caps at 8. LLM off → empty list + note; generation failure → generic note; the UI surfaces each suggestion with its reason and adds it with one click (existing `createSkill` duplicate guard still applies).
- **Tailored resumes get JD-matched projects — chosen by the user, before tailoring.** When a resume is tailored for a job, the Projects section is **replaced** by career-graph projects matching the job. The tailor UI now has a **picker step**: `POST /resumes/improve/projects-suggestions` returns the top 5 matches (deterministic weighted scoring over name/role/description/languages/README/linked skills — matching is never left to the LLM), each with a drafted description and an `already_in_resume` flag; the user picks up to 4 and the names are passed back as `selected_projects` on the preview/improve request (auto top-2 fallback when none are picked). One batched `MATCHED_PROJECTS_PROMPT` call writes **a single description per project** — one concise phrase (at most 280 chars) led by a strong past-tense action verb (work-experience style) that flows Problem → Solution → Result in a single breath — grounded strictly in the project's evidence (description + README + languages); exactly one phrase is the only shape that passes normalization. Projects already on the resume keep their identity with the phrase replaced, missing matches are added as new entries, and everything else in the section is dropped (visible as `removed` changes in the diff preview). The merge runs after the safety nets and before refinement (keyword injection still polishes the new phrases), and is no-op safe: no matches, no LLM, no selection, or any failure leaves the resume untouched.
- **Resume summaries follow the C-WHAT formula.** When the tailoring pipeline rewrites the summary (`DIFF_IMPROVE_PROMPT` path `"summary"`, and the legacy full-tailor prompt), it must cover all four elements in 2-3 concise sentences: **WHO** = professional identity (title, seniority, years), **WHAT** = specialization + job-relevant skills, **RESULT** = measurable impact/evidence (only facts present in the original resume — never invented), **HOW** = technologies and methodologies used.
- **Technical skills are grouped by category and trimmed to job-necessary ones.** The tailoring pipeline ends with a deterministic step (`trim_and_group_skills` in `app/services/skill_presentation.py`) that (1) **splits** legacy comma-joined list items into individual skills (same paren-safe splitter the `AdditionalInfo` validator uses), (2) **trims** the flat `technicalSkills` list to skills that match the job description (JD-matched, kept first) or are proven elsewhere in the resume text (evidence-backed — word-boundary match against the whole original resume), original order preserved, `_MAX_KEPT_SKILLS` = 24 cap, and (3) **groups** the kept skills into ordered English categories (Languages, Frontend, Backend, Databases, Cloud & DevOps, Architecture, AI/LLM, Tools fallback) written to the resume data as `additional.skillGroups` (`SkillGroup{name, skills}`). Category matching is variant-tolerant: exact alias first, then containment (alias inside skill, e.g. `"RESTful APIs"` → Backend) guarded by a 4-char minimum so short aliases like `C` never swallow unrelated skills; real-world variants like `"REST APIs"`, `".NET / ASP.NET Core"`, `"RxJS"` land correctly. No LLM, no guesses: the diff shows each removed skill as a `removed` change, and a warning (`"Removed N skill(s) not relevant to this job: ..."`) surfaces in the preview. It runs after refinement (refiner-injected JD skills survive) and is no-op safe — no dict/skills/JD terms/all-dropped → resume untouched with a "not trimmed" note. Templates render groups (one bold `Name:` line per category) when present, flat layout otherwise; ATS scoring is unaffected because JD skills survive by definition.
- **Chat is non-streaming** request/response with the last ≤8 turns as history; answers render as Markdown.
- **Prompt-injection hygiene:** user questions are run through `_sanitize_user_input` (same guard as the improver pipeline); memory content is truncated before prompt assembly.
- **Tracker enrichment:** applications gain optional `rejection_reason` + `interview_rounds` (editable in the card detail modal, used by memory + gap analysis). The columns are added to existing databases via an idempotent `ALTER TABLE` migration.
- **LLM-optional:** insights narrative, ROI advice and chat answers degrade gracefully (`null` narrative/advice, 503 on `/ask`) when no LLM key is configured; the rest of the page works fully offline.
- **Comma-separated extraction:** skills, languages, certifications and awards extracted from a resume are split on commas/semicolons (commas inside parentheses preserved) and deduped case-insensitively — at parse time in `AdditionalInfo._normalize_string_fields` (see `app/schemas/models.py`) and again in `seed-from-master` (`_merge_resume_skills` / `_string_list_from_resume`) so previously-parsed resumes also get clean, individual entries.
- **Market Position is a deterministic heuristic, not an ATS score.** `POST /profile/market-position` (`app/services/market_position.py`) scores every tracked skill from local evidence (proficiency 40%, years 30%, last-used recency 20%, matching certifications 10% — weights of missing fields are dropped and the rest renormalized, so absent data is never scored as weakness) and maps the composite through a modeled candidate distribution (piecewise curve: 50 = 50th percentile, 90+ = expert) into a 0–100 percentile. Skills aggregate into domains (Backend, Frontend, Cloud & DevOps, Data & ML, System Design) by word-boundary keywords over skill names, role titles and projects (name, role, description, languages, 2000-char readme preview); domain percentile = 70% member-skill average + 30% experience evidence, where experience = 65% role-title years (capped 20y, via `_YEARS_CURVE`) + 35% matched-project count (capped 12, via `_PROJECTS_CURVE`) — domains with only titles/projects get partial credit (experience × 0.7), and domains with no evidence at all are omitted. The response also names the user's **exact position**: `current_role` = seniority band + default domain title ("Mid Backend Engineer"), `specialization` = the top skills (≥40th percentile) of the strongest domain, and `recommended_roles` = best-fit roles to pick from a built-in role catalog (`_ROLE_CATALOG`, up to 5) scored 75% domain percentile + 25% skill-overlap with a "Matches your …" / "Fits your … profile" reason. The template verdict leads with the position ("You're a Mid Backend Engineer specializing in Python."), then says where the user is strong ("You're strong for Junior/Mid Backend roles"), flags senior-level gates with no ≥50th-percentile skill evidence ("You're underqualified for Senior roles requiring Kubernetes, infrastructure as code, and distributed systems"), and closes with the best next picks ("Best next picks: Python Developer, React Developer, and API Developer."); it degrades to a "developing profile" note when there is no data — never invented market numbers, fully unit-tested, works with the LLM off.

## Career Graph (Phase 1)

The career graph stores the resume's education, projects and achievements as their own tables plus skill↔entry edges, so the profile page has dedicated **Education / Projects / Achievements tabs** and the AI advisor sees them in memory.

- **Tables:** `career_education`, `career_projects`, `career_achievements`, `career_entry_skills` (edge `entry_type` ∈ `experience` (index into `work_experience`) / `project` (by `project_id`); unique `(entry_type, entry_key, skill_name)`).
- **Single fulfill path:** `fulfill_profile_from_resume` in `app/services/career_graph.py` is called by **both** `POST /profile/seed-from-master` **and** automatically after a master-resume upload / wizard finalize (`routers/resumes.py`, `routers/resume_wizard.py`) — the manual and automatic flows can't drift apart. Auto-fulfill is best-effort: it logs and never fails the upload that triggered it.
- **Replace-when-present seeding:** the resume's education / projects / certifications **replace** their tables when the resume has the section; anything the resume lacks is left untouched. Personal info / summary / experience / languages / awards replace when present; technical skills **merge** (never replace).
- **Skill edges are deterministic:** `extract_entry_skills` word-boundary-matches the entry text against catalog names + aliases, but only links skills the user actually listed in the resume's `technicalSkills` — prose like "I can go build things" never creates a Go edge. Edges are rebuilt on every fulfill; `prune_career_experience_edges` runs on fulfill and on `PUT /profile` so a deleted/reordered experience row never leaves an orphan edge (project edges die with the project via cascade).
- **GitHub import is cached and idempotent:** the import flow reuses `GET /github/github/repos` (10-minute in-process cache + frontend TTL), so repeated imports never re-hit the GitHub API; imported projects are stored in `career_projects` (`languages` JSON + `readme` snapshot columns, additive `ALTER TABLE` migration in `db_engine.py`) and re-imports update in place keyed by repo URL. The UI opens a multi-select dialog (repos, visibility, languages); the projects tab shows language chips + a collapsible README per project.
- **Memory:** `build_career_memory` includes capped education (8) / projects (10, with linked `skills`) / achievements (15), each description ≤400 chars; `career_data_fingerprint` and `reset_database` cover the new tables.

## API Endpoints

| Endpoint | Description |
|----------|-------------|
| `GET /profile` | Bundle: `{profile, skills, certifications, education, projects, achievements}` (auto-creates the profile row) |
| `PUT /profile` | Upsert profile (contact, summary, goals, targets, salary); prunes orphaned experience edges |
| `POST /profile/seed-from-master` | Copy personal info from the master resume (`404` without one) |
| `POST /profile/skills` | Add skill (`201`; `409` case-insensitive duplicate) |
| `PATCH /profile/skills/{id}` | Update skill (`409` rename-onto-duplicate, `404` unknown) |
| `DELETE /profile/skills/{id}` | Delete skill |
| `POST /profile/certifications` | Add certification (`201`) |
| `PATCH /profile/certifications/{id}` | Update certification |
| `DELETE /profile/certifications/{id}` | Delete certification |
| `GET /profile/education` | List education entries (insertion order) |
| `POST /profile/education` | Add education (`201`; `institution` required) |
| `PATCH /profile/education/{id}` | Update education |
| `DELETE /profile/education/{id}` | Delete education |
| `GET /profile/projects` | List project nodes (insertion order; includes `languages` + `readme` when GitHub-imported) |
| `POST /profile/projects` | Add project (`201`; `name` required; optional `languages`/`readme`) |
| `PATCH /profile/projects/{id}` | Update project (partial edits preserve `languages`/`readme`) |
| `DELETE /profile/projects/{id}` | Delete project (skill edges removed with it) |
| `POST /profile/projects/import-from-github` | Import GitHub repos as projects (body `{repo_urls?: string[]}`, empty = all; `401` when no GitHub token; upserts keyed by repo URL, capturing name, description, languages and README) |
| `GET /profile/achievements` | List achievements (insertion order) |
| `POST /profile/achievements` | Add achievement (`201`; `title` required, `date` `YYYY`/`YYYY-MM`) |
| `PATCH /profile/achievements/{id}` | Update achievement |
| `DELETE /profile/achievements/{id}` | Delete achievement |
| `GET /profile/memory` | Career memory bundle (debug/reuse) |
| `POST /profile/ask` | Career advisor chat (`503` when LLM off) |
| `GET /profile/insights` | Funnel stats + optional LLM narrative |
| `POST /profile/skill-roi` | ROI table (+ optional LLM advice) + job-focused sections (`gaps`, `strengthen`, `rest`) |
| `POST /profile/market-position` | Deterministic market position: per-skill + per-domain percentiles, seniority/readiness bands, exact `current_role` + `specialization`, best-fit `recommended_roles` and a template verdict (no LLM, no external data) |
| `POST /profile/skill-resources` | Verified learning resources per skill (body `{skills: [...], refresh?}`; cached 7 days; LLM-proposed + URL-verified; note when LLM off) |
| `POST /profile/skill-suggestions` | AI "forgotten skills" suggestions over local career data (`{skills: [{name, reason}], note?}`; empty + note when LLM off) |
| `GET /profile/suggestions?field=` | Tag suggestions (`career_goals`/`target_roles`/`target_locations`) from scraped jobs + work history; goals are role-derived templates localized to the content language |
| `POST /resumes/improve/projects-suggestions` | **Picker step before tailoring**: top-5 JD-matched career projects, each with drafted single-phrase Problem→Solution→Result descriptions, a deterministic match score, and an `already_in_resume` flag. Body `{resume_id, job_id}` (same as improve preview). Empty list = no matches. |
| `POST /resumes/improve/preview` (extended) | `ImproveResumeRequest` now accepts `selected_projects: [names]` — when provided, the Projects section is replaced with exactly those career projects (selection order, max 4); otherwise the auto top-2 fallback applies |
